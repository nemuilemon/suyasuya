# PVT（反応時間テスト）の取り込み

**状態：案。未実装。**

## なぜ入れるのか

suyasuya が抱える構造的な問題がひとつある。
睡眠データだけでは、**日中の機能がどう変わったかを直接観測できない**。

「昨夜は 5 時間でした」——それは user も知っている。
スコアを提示するアプリが響かないのは、多くの場合これが理由だ。

PVT は、user が**主観だけでは気づきにくい変化**を agent に与える。

### 根拠

[Van Dongen ら（2003）](https://pubmed.ncbi.nlm.nih.gov/12683469/) の実験では、
4 時間または 6 時間/夜の睡眠制限を 14 日間続けると、認知課題の成績が累積的に悪化し、
条件・課題によって最大 2 晩の徹夜に相当する低下が見られた。

問題は次の点にある。
**主観的な眠気の変化は、成績の累積的な悪化に追いつかなかった。**

つまり主観的な眠気だけでは、機能の低下を十分に捉えられないことがある。
この隙間こそが、agent が声をかける正当な理由になる。

> 最近、反応時間が延びる傾向がある。今日は早めに切り上げよう。

これは睡眠時間の提示に加えて、**日中の反応を計測した観測**だ。
README の「agent が読んで、必要なときにだけ声をかける」を、
言えることの中身の側から裏打ちする。

## 記録の負担を減らす方針との関係

README が退けているのは**細かな睡眠記録を負担させること**（記録が対象への注意になる）。
睡眠の入力は画像の読み取り結果の確認・承認、または主要数値の手入力に絞る。
PVT が測るのは睡眠ではなく**日中の機能**なので、対象が違う。
「今日の集中力を測る」枠組みにする。ただし測定自体の負担は残る。

ただし user への要求が 1 つ増えるのは事実。README には 2 本立てで書いた。

- 睡眠記録の確認・承認（画像の読み取り、または主要数値の手入力）
- 能動的な入力（PVT）＝ 結果の計測

## 何を測るか

標準の PVT は 10 分。長すぎるので **PVT-B**（[Basner ら, 2011](https://pmc.ncbi.nlm.nih.gov/articles/PMC3197786/)）を採る。

| | |
|---|---|
| 所要時間 | 3 分 |
| 刺激間隔 (ISI) | 1〜4 秒のランダム |
| 課題 | 画面にカウンタが現れたら、できるだけ速く反応する |
| lapse 判定 | 355 ms 以上（標準 PVT の 500 ms ではない） |

記録する指標：

- **median RT** —— 中央値。外れ値に強い
- **lapse 数** —— 355 ms 以上の反応の回数
- **slowest 10% の平均** —— 崩れ方の裾を見る
- **false start 数** —— 刺激前、または刺激後 100 ms 未満に反応した回数。通常の RT 集計から除外する

催促の判断には、**単発の値より複数日の傾向を使う。**
PVT の変化だけで、睡眠の規則性が原因だとは断定しない。

## 運用上の制約

計測条件を揃えないとノイズに埋もれる。

- **毎日ほぼ同じ時刻**に打つ（起床後の一定時間が望ましい）
- カフェイン摂取の前後どちらかに固定する
- 同じデバイス・同じ入力手段（キーボードなら常にキーボード）

**PVT をいつ測定するかは user が設定する。** 設定 UI で測定時刻と
タイムゾーンを保存し、control の scheduler がその時刻に測定を促す。
agent が測定時刻を勝手に変更することはない。

予定時刻とは別に、実際の打鍵日時を記録する。
設定変更や予定からのずれがあっても、測定条件を確認できるようにする。

## 実装の重さ

PVT 自体は**軽い**。canvas とタイマーと乱数だけで、推論もモデルも要らない。
screenshot の読み取り pipeline より明らかに安い。

想定するデータの形：

```
session: 打鍵日時 / device / 反応時間の配列
derived: median_rt / lapses / slowest10_mean / false_starts
```

生の反応時間配列は捨てずに持つ。指標の定義を後から変えられるようにしておく。

## 着手順への影響（重要）

**PVT のデータには lead time がある。コードにはない。**

傾向線が意味を持つには 2 週間分ほしい。**agent loop より先に、雑でいいので
記録部分を立てて打ち始める。** seed した偽データの曲線と、
実際に積み上がった曲線では説得力が違う。
