## 提出物

ダッシュボードでプロジェクトを作成し、以下を登録して提出。

- [ ] **GitHub リポジトリの連携**（GitHub App をインストール。公開・非公開は問わない）
- [ ] **デプロイした URL**
- [ ] **プロジェクトの説明**（対象ユーザー像・課題・ソリューションと特徴）
- [ ] **システムアーキテクチャ図の画像**
- [ ] **3 分程度のデモ動画**（自作・YouTube に公開して URL を登録）
- [ ] Zenn 記事 —— **任意**。書く場合は**カテゴリ「Idea」**で公開して URL を登録

認証が要るなら **テストアカウント**を作り「動作確認の方法」に認証情報を書く。
**ソーシャルログインやメール受信が必須のログイン方式は避ける**（審査できないため）。
そのテストアカウントで見える**サンプルデータ**も用意する。審査員はこれを基準に見る。

提出締切後、プロジェクトページ（説明・アーキ図・デモ動画）は一般公開される。
**リポジトリとデプロイ URL は審査にのみ使われ、公開されない。**

## リポジトリの扱い

- 審査対象は**連携リポジトリのデフォルトブランチ**
- **提出時点の状態を 12/1 まで保つ。** 連携解除・削除も不可
- 提出後も開発したい場合は**別ブランチ**で。デフォルトブランチは凍結
- 12/1 まで**デプロイして動作確認できる状態**を維持する
- コードは「主要機能がモックではなく実際に実装されていると分かる程度」含める。
  どこを開発したか・パッケージ化した部分はどこかの**構成説明を必ず添える**

## 審査基準（第 5 回で刷新された）

今回のテーマは「**作れる**」から「**使える**」。自律性を持ちつつ、
**ガバナンスとセキュリティを意識して設計された**エージェントを募集している。

| 基準 | 中身 |
|---|---|
| **課題の新規性と解決策の有効性** | 多くの人が抱えつつ未解決の課題を発見できているか。ソリューションが核心に効き、実質的な価値を出しているか |
| **自律性・エージェントらしさ** | 単純な自動化を超え、状況を判断して自律的に動くか。**その自律性が適切に管理・制御され、可観測性とセキュリティへの配慮を持つか** |
| **実装品質と拡張性** | 高い品質で実現できているか。拡張性・運用性・費用対効果を考慮した実用に耐えるものか |
